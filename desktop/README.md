# 拾影桌面版 0.4.28 网盘内置下载本地预览

普通文件和大视频使用桌面版，网页里的识别入口继续放在拾影插件中。

## 开始使用

1. 运行 `拾影-0.4.28-网盘内置下载-安装预览.exe`，点击「安装并连接」。默认安装到当前用户 `%LOCALAPPDATA%\Programs\Shiying`，无需管理员权限；可选择创建快捷方式。普通文件与 BT 核心组件已包含，无需额外准备。程序未签名，本版仅供本地审查。更新前正常关闭拾影，保留已有任务和组件；网盘入口需加载 0.4.30 或更新 Chrome 插件，旧版插件的视频入口仍兼容。
2. 在主界面粘贴链接，或从右上角菜单选择「新建下载」，粘贴普通 HTTP/HTTPS 文件链接，选择保存位置。视频页面或 m3u8 / mpd 链接选择「网页视频」，需要 MP3 时选择「仅声音 MP3」。
3. 每张任务卡片右侧可直接「暂停」或「继续」，失败、暂停、已完成等可移除状态会在操作按钮下直接显示「删除任务」，确认时默认勾选“同时删除文件”，取消勾选则保留文件；点「···」可查看更多操作；键盘空格也可暂停 / 继续。从任务行菜单进入多选，或 Ctrl 点击任务后，可批量暂停、继续或移除记录；只处理符合操作条件的所选任务。删除前可选择保留文件和未完成数据。
4. 「批量添加」接受每行一个地址，一次最多 100 条；本次完全相同的地址会去重。全部校验通过后统一加入队列，地址出错时不添加整批。视频页面需选择视频类型；单独声音选择 MP3。
5. 新任务默认按类型放入视频、音乐、压缩包、程序、图片、文档、模型或其他子文件夹；可在确认框取消，也可在设置中关闭默认分类。按服务器最后提供的实际文件名分类。已有任务和文件不搬移。

关闭窗口时暂停任务，下次启动后手动继续。桌面版独立运行，下载期间可关闭 Chrome。

默认保存到 Windows 用户下载目录的「拾影」文件夹。主界面顶部的保存位置旁可直接点「选择文件夹…」更改并记住默认目录；新建、批量任务的确认框均有「选文件夹」按钮指定本次位置。修改默认目录不会搬移已有任务；按类型归档仍由确认框中的选项控制。设置里也可修改目录、代理和连接数。代理默认使用本机 `http://127.0.0.1:7897`；不使用代理时清空这一项。普通文件默认每个任务最多 8 条连接，可设为 1–16 条；文件队列可设 1–4 个并行任务，视频队列可设 1–2 个，默认仍为 2 / 1。限速单位为每任务 KiB/s，0 表示不限；连接数和限速用于新开始或继续的任务。实际并发数、速度和能否续传取决于服务器。

## 网盘内置下载（0.4.28 本地预览）

本轮使用作者公开的 123 字体分享完成真实文件下载（QiushuiShotai.woff2，9,485,296 字节）、暂停、测试进程重启续传，MD5 与来源元数据一致。测试使用独立引擎与状态目录，限速 256 KiB/s，未安装或执行字体，也未接触已安装程序及个人 Chrome。123 新分享按网页原有流程先检查配额，再读取 Web 下载线路；遇到付费、流量不足或权限限制会明确提示，不创建付款操作。Chrome 插件使用 0.4.30，桌面版使用 0.4.28 或更新版本，连接检查会阻止不支持新网盘协议的旧桌面版。

安装同版本插件后，在支持的网盘页打开插件并点击「开启拾影下载」，允许这个网盘的可选权限。原下载按钮旁新增小按钮，勾选文件后点「拾影下载」即可按记住的目录后台入队，不显示确认框、不拉出主窗口。只有主动点「查看任务」「保存位置」才打开桌面窗口；新任务的类型归档沿用桌面设置。无需篡改猴，不改原下载按钮，不接管 Chrome 普通左键下载。隐藏按钮后可在插件中恢复。百度首次可能需要在插件中另点「百度授权」，自行确认百度页面的授权。

八家适配器使用隔离页面/API 数据检查，并完成 Cookie 认证的本地文件分段、暂停、重启续传和 SHA-256 一致性检查；尚未完成八家真实账号验收。部分分享页不支持，阿里需列表视图；每批最多 100 文件。链接过期需回网盘重新取得，重新取得的文件作为新任务，不自动续接旧地址。网盘任务 Cookie 仅在本机 DPAPI 加密保存，下载完成清除；百度授权也仅在本机密封存储。来源与许可见源码根目录 NOTICE.md、PRIVACY.md。

## 与 Chrome 插件共用界面

桌面程序直接加载插件的 `css/shiying.css` 和原品牌图标，通过内嵌 WebView2 渲染相同的网页控件。主窗口支持调整大小与最大化，另保留迷你窗；字号、按钮、菜单、链接输入、进度胶囊与插件共用样式。新建确认、设置、BT 勾选、详情与迷你窗也在这套界面中，不再显示之前手绘的 Windows 任务卡片。

新建前可以确认类型、清晰度和本次保存文件夹；浏览器传入的实际清晰度与签名地址在主程序中绑定，界面不能把它们替换成另一组画面和声音。新任务保存目录在顶部始终可见。视频组件依旧按需准备，普通文件与 BT 下载仍由原来的下载管理器执行。

界面使用系统中的 Microsoft Edge WebView2 Runtime，安装包包含经过校验的 SDK 适配文件，不包含浏览器用户资料。这个本地预览已在当前电脑的独立隐藏窗口中检查。界面资源全部内嵌，不访问远程网页；下载流量由下载引擎处理。SDK 版本、来源和哈希见 `interface-dependencies.json`，第三方许可见 `licenses/WebView2-SDK.txt`。[WebView2 官方文档](https://learn.microsoft.com/microsoft-edge/webview2/get-started/winforms)。

## 轻量窗口

主界面与 Chrome 插件共用网页组件。配对、视频组件、批量添加和设置收进右上角「···」菜单。任务行右侧「···」可进入多选，Ctrl 点击任务也能多选，选中后显示批量操作。点「迷你窗」只显示一个任务的真实进度，可暂停、继续或切换下一项；「展开 ↗」恢复原窗口大小、选择与详情状态。迷你窗默认不置顶。选择「收起到托盘」隐藏窗口但继续运行，双击托盘图标恢复；直接关闭主窗口仍会保存并暂停任务。

## 下载详情

点任务的「查看详情」、双击任务，或在任务上按 Enter，在任务下方展开详情，再次操作即可收起；等待选择文件的 BT 任务可点击「选文件」打开勾选窗口。单纯选中任务不会展开详情。轻量详情显示真实大小、已下载量、速度、剩余时间、续传、连接数和分段图，未知数据保持未知。点详情中的「下载地址与保存位置」展开完整地址和保存路径，完整内容保留在独立的可滚动地址区域中，再点即可收起。BT 详情中的「选择 BT 文件」会在同款界面中打开文件勾选窗口。

普通文件的大小、已下载量、速度、连接数和数据块位图来自 aria2 `tellStatus`。剩余时间按未下载字节与当前速度估计，暂停、排队、无速度和未知大小时不显示假定时间。分段区域按文件位置把真实数据块归为最多 16 个区间，显示每段的已完成量、大小与进度；只计完整数据块，写入中的块不计入，因此分段合计可能暂时小于总已下载量。它表示文件区间，**不是固定线程列表**。文件位置列的悬浮提示提供精确字节范围。

续传能力通过 GET `Range: bytes=0-0` 的实际响应确认；不是只看 `Accept-Ranges` 声明。支持分段且具有可核对的版本信息时显示「支持（需核对）」。源文件变化、不支持分段或缺少版本信息时，恢复会停止并保留原数据，不把它们当作安全可续传。大小未提供时显示「未知」，空文件明确显示 0 B。

视频按下载内核的结构化进度显示**当前画面轨 / 声音轨**的已下载量、大小、速度、剩余时间与分片计数；估算大小会标注「约」。合并后才显示成品文件大小。视频内核没有提供每个分片独立的字节进度，因此这类任务不绘制虚构的分段条，也不把当前轨大小冒充整个视频总大小。

旧任务可打开详情；缺少的记录显示未知，仍存在的完成文件可以读取实际大小。详情只读取管理器快照，不额外启动下载或浏览器连接。

字段来源：[aria2 tellStatus](https://aria2.github.io/manual/en/html/aria2c.html#aria2.tellStatus)、[yt-dlp progress-template](https://github.com/yt-dlp/yt-dlp#output-template)。

## 磁力链接与 BT 种子

- 磁力链接：在主界面粘贴链接，或从右上角菜单选择「新建下载」，粘贴 `magnet:?xt=urn:btih:...`，自动识别为 BT。可在「批量添加」中每行粘贴一个磁力链接，也可与普通文件链接一起添加。相同 InfoHash 不重复创建任务。
- 本机种子：打开右上角「···」菜单，点击「导入 BT 种子」，选择 `.torrent` 文件并确认保存位置，然后勾选文件。导入时验证元数据并保存本机副本，之后不依赖原种子文件的位置。
- 新任务默认一个文件也不勾选，至少选一个非空文件后才能点击「下载所选文件」；也可主动「全选」或「清空选择」。窗口显示路径、大小、已有数据和所选合计。「稍后选择」或关闭窗口会保留等待状态，不开始内容下载；在任务列表点击「选文件」可继续。
- 下载中先暂停，再在详情页点「选择文件」调整；已完成任务也可改选其他文件。文件选择随任务保存，正常重启后继续沿用。0.4.5 的未完成 BT 任务升级后要求重新确认选择，已完成任务保留原记录。改选不删除已有数据；删除任务时按确认框中的选项处理。
- 保持种子原有目录，每个任务使用独立文件夹。大小、已下载量、总进度和剩余时间只统计所选文件；已下载量按校验完成的数据块统计，写入中的块暂不计入。「查看文件 / 查看分段」切换明细；分段图保留整个种子的物理位置，未选区间不会因为所选文件完成而全变绿。
- BT 数据块可能跨越相邻文件；校验所选文件时可能在未选文件中留下少量边界数据，这部分不计入所选文件总量。已有文件不会自动删除，部分选择完成后的 `.aria2` 状态文件也会保留，以便以后改选或补下。参见 [aria2 select-file](https://aria2.github.io/manual/en/html/aria2c.html#cmdoption-select-file)。
- 支持暂停、继续以及正常关闭后重新打开继续，恢复时由 aria2 校验已有数据块。删除时可选择保留文件和未完成数据，并释放内核记录以便重新添加。
- 磁力先从节点获取种子信息并核对 InfoHash、文件名和路径，然后停在「等待选文件」。获取列表不自动下载内容；确认勾选后才进入内容队列。获取信息期间大小保持未知，不显示虚构进度；无可用节点时显示等待节点，可暂停后稍后继续。
- BT 节点、DHT 和 UDP Tracker 直接联网，不通过设置中的 HTTP 代理；HTTP/HTTPS Tracker 使用该代理。下载期间按 BT 协议交换数据，上传总速上限默认 512 KiB/s，可在设置中改为 16–8192 KiB/s，保存后对运行中的 BT 会话生效；完成后停止做种。普通文件任务不会启动 BT 会话。
- 支持常见 BTv1 磁力（40 位十六进制或 32 位 Base32）及带 BTv1 信息的混合种子；暂不支持纯 BTv2。种子元数据上限 4 MiB、文件数上限 3000，拒绝越界路径、重复或冲突路径、Windows 设备名及符号链接。

本地回归使用自建 Tracker、本机节点和生成的原始字节文件，验证真实 BT 与磁力元数据交换、默认未选保护、仅选第一或第二个文件、磁力获取列表后等待、跨文件边界、SHA-256、改选保留已有文件、同一会话及重启续传；关闭公共 DHT/PEX 并绑定回环地址，新增 DHT 测试也仅连接本机引导，不访问公共 BT 网络。勾选、全选、清空、计数、详情状态及最小窗口 / 150% 缩放的控件边界在隐藏状态检查，未进行个人屏幕或可见界面验收；公网 DHT、资源可用性和速度没有因此得到保证。

### 0.4.7 的节点与队列优化

- DHT 首次启动补充 `dht.transmissionbt.com:6881` 引导地址；复用本机 IPv4 路由缓存，在系统支持 IPv6 时尝试 IPv6 DHT，并使用独立缓存。无需等待已有 Tracker 先提供节点。公网上的连通性仍取决于运营商、UDP、IPv6 与防火墙。
- 公开种子的内容下载补充 OpenTrackr 的官方 UDP 地址，保留种子原有 Tracker；私有种子和尚未获取列表的磁力不添加公共备用 Tracker。内核按种子私有标记处理 DHT / PEX。Tracker 公布的请求间隔由内核遵守，不强制高频查询。
- 每个 BT 任务常规节点上限由 55 调为 96；下载低于 1 MiB/s 时由内核尝试扩展连接。设有更低下载限速时，找节点的速度阈值也随之降低，不把用户限速误当作资源不足。底层内核的临时扩展策略仍可能增加连接数量，96 并非整个应用的绝对连接总上限。
- 内容队列沿用设置的文件 / BT 并行数，磁力元数据另有最多 2 个名额，总 BT 内核活动任务不超过 6 个。排队的磁力可以先获取列表，内容仍须勾选确认。
- BT 连续 60 秒没有下载进展且同类队列有其他任务时，会暂停该内核任务并暂时让出名额；至少 30 秒后加入队尾，名额可用时在同一内核任务上继续，避免旧任务重试一直挡住后面的任务。文件校验或排队校验不算无进展。无其他任务时保持寻找节点。手动暂停会停止自动重试，改选与续传保留原有数据。
- BT 写缓存由 16 MiB 调为 64 MiB，控制文件自动保存间隔由 1 秒调为 5 秒，减少碎片写入；正常关闭仍保存状态，恢复仍执行分块校验。上传上限可调，避免固定过低的上传额度长期限制节点互传，也可按实际网络调低。

新增回归只使用本机生成的字节、空 Tracker、失效和有效的回环节点，以及本机 BEP5 DHT 引导。验证 Trackerless 磁力发现节点、冷热任务调度、元数据独立名额、同一 GID 的暂停 / 自动继续及手动暂停保护。调度测试通过测试时间戳模拟 61 秒无进展和重试到期，实际调用内核暂停 / 继续；不代表公网吞吐提升了某个百分比。所有控件保持隐藏，无屏幕或鼠标操作。

参数依据：[aria2 BT 参数与 RPC](https://aria2.github.io/manual/en/html/aria2c.html#bittorrent-specific-options)、[aria2 DHT 初始化实现](https://github.com/aria2/aria2/blob/release-1.37.0/src/DHTSetup.cc)、[Transmission 引导节点](https://github.com/transmission/transmission/blob/main/libtransmission/tr-dht.cc)、[OpenTrackr 官方地址](https://opentrackr.org/)。

### 0.4.8 的续传与完成状态修正

- 暂停前暂存本次运行中已连接的最多 64 个节点，继续内容下载时优先使用这些节点；缓存 10 分钟后失效，仍保留原 Tracker 与 DHT。节点只保存在内存，不写入任务记录或发送给外部 Tracker；回填节点使用仅绑定 127.0.0.1、带随机路径的内部接口，随管理器退出关闭。私有标记与原始 info 字典不变，原始种子副本不改写。跨进程继续仍通过原 Tracker 和持久化 DHT 路由重新发现节点，无法保证无供源资源立即恢复。
- 继续时仍由内核校验已有块；缓存节点不跳过校验。本机回归特意改坏暂停文件中的字节，重新继续后修复并核对完整 SHA-256。
- 内核已确认所选分块完成、并且没有进行或等待校验时，取消仍在等待的 Tracker 收尾请求；仍等待内核落盘、关闭文件并返回最终 `complete` 才显示成功，出现错误则保留失败状态。仅进度达到 100%、大小相等或图形进度四舍五入不会触发成功。短暂收尾阶段说明“文件已校验，正在保存并结束连接”。
- 本机回归包含只返回一次节点的 Tracker、12 秒延迟的完成 / 停止响应、缓存失效回退、原种子不变、私有标记保留、损坏数据修复；另使用此前公开资源在独立目录后台复测。具体公网等待与校验结果以本次交付的实测记录为准。

后台检查入口：`python scripts/bt-check.py`、`powershell -File scripts/details-check.ps1 -Headless`、`powershell -File scripts/startup-check.ps1`。这些入口不显示窗口、不操作鼠标；原有可视化审查脚本仍会显示窗口，后台工作不要运行它们。

### 0.4.9 的重启续传与原因提示

- 近期已连接节点现在保存到每个任务自身的 `data/partial/<任务编号>/recent-peers.json`，有效期最长 10 分钟，最多 64 个；下载中定期更新，正常关闭与暂停也保存。重新打开后优先尝试原节点，依旧校验已有文件。缓存绑定原种子 InfoHash，不保存旧的内部接口地址。失效、格式损坏、错误 InfoHash 或不合法节点均忽略并回到正常发现，不阻止任务恢复。缓存不能使已经离线的节点恢复在线。
- 缓存只在本机使用，不发送给外部 Tracker；任务完成或移除记录时清除此项短期缓存，已有文件保留。该行为更新了 0.4.8 中“仅存内存、退出后清空”的历史实现。
- 任务列表的说明与详情底部现在显示当前原因和建议：正在校验、等待校验、等待名额、获取种子信息、接收分块、接近实际限速、尚未发现节点、已连上但对方未传输、等待下载源回应。提示依据内核实时状态，节点明细及限速最多每 3 秒刷新一次；未收到可靠状态时明确原因尚未确认。
- 没有单凭速度为零判断 Tracker 故障、DHT 被封锁或源站缺块。获取不到这些证据时保留未知，建议继续等待或核对网络。暂停与完成状态覆盖旧的活动提示。
- 后台回归新增不同操作系统进程间恢复：原私有 Tracker 只首次提供节点且关闭 DHT/PEX，第一进程在下载中退出，第二进程从磁盘节点缓存恢复；另故意改坏暂停文件，继续后修复并验证完整 SHA-256。提示样例和详情控件在隐藏状态验证，不操作用户屏幕。

## 从插件发送

1. 在 Chrome 开发者模式加载本次 `Chrome插件` 文件夹。安装器不会替用户安装浏览器扩展，也不会更改商店版。预览版使用固定本地 ID，保留 `manifest.json` 中的 `key` 即可在不同目录保持一致。
2. 安装器自动登记配套插件与本机程序路径。在插件菜单打开「桌面下载」，点击「检查连接」，按 Chrome 提示允许本机通信。
3. 若使用其他 ID 的本地版本，点击「一键重新配对」，按浏览器提示打开拾影，并在桌面确认这个扩展；连接页通常无需手工复制 ID。
4. 选择清晰度后点「交给桌面版下载」。桌面窗口显示确认框，选择保存位置后开始。连接检查只发送 ping 并返回版本，不创建下载任务。

首次视频任务会自动准备所需的 yt-dlp、FFmpeg；普通视频页面另外需要 Node。浏览器已选音视频轨、直接 m3u8 / mpd 链接不额外下载 Node。组件来自 `components.json` 内固定的 HTTPS 官方发布地址，下载大小和 SHA-256 均固定；FFmpeg 压缩包及其中可执行文件分别校验。不会下载远程脚本或远程组件清单，不会自动更新组件版本。

任务列表显示「准备组件」及进度，组件阶段变化时说明文字及时重画；可暂停，继续时续传。临时连接中断和 HTTP 408 / 429 / 500 / 502 / 503 / 504 最多自动重试两次，使用已有缓存续传；等待重试时也可立即暂停。持续失败会说明已保留进度，并提示检查网络或代理后点击「继续 / 重试」。已验证可用的组件不会重复下载；校验失败不会自动重试、安装或运行，原组件保留。代理错误可在设置中修改或清空代理后继续重试。一次约需 110 MB 下载流量（yt-dlp + FFmpeg 压缩包），需要 Node 时再增加约 87 MB；具体大小见清单。完成准备后以后复用本机文件。

B站、YouTube 视频页把鼠标移到播放器上，会显示「拾影下载」。点击打开拾影侧栏；浏览器不支持该打开方式时，会打开与当前视频关联的拾影标签页，再选择画质或交给桌面版。按钮仅是快捷入口，尚未在用户个人浏览器中验收网站兼容性；全屏时隐藏，× 可在本页隐藏，暂停识别也会隐藏。没有为其他网站添加悬浮按钮。

插件只在点击发送时申请本机通信权限。B站与 YouTube 发送已读到的实际画面和声音地址；Cookie、密码和完整浏览记录不传给桌面端。需要额外 Cookie / Authorization 的普通媒体会提示使用原下载入口。签名媒体地址可能过期，遇到 403 或过期提示应回到网页重新读取，再发送一个新任务。

安装版请保留默认安装位置。安装与用户主动重新配对会登记当前用户的 Chrome / Edge Native Messaging、`shiying-desktop` 连接协议和 Windows 卸载项；保留此前登记过的有效扩展 ID，不扫描浏览器配置或读取 Cookie。便携版移动后可点击「连接浏览器 → 修复连接」。日常启动不重新登记。

## 数据和完成文件

任务记录、来源链接和未完成数据保存在桌面版同目录的 `data` 中，不上传给开发者。任务记录可能含临时签名网址，请不要公开上传这个目录。应用正常关闭时保留可恢复数据。

普通文件恢复前会比对 ETag / Last-Modified 与文件大小；源文件变化或缺少可核对的版本信息时会停止恢复并保留原数据。可以新建一个下载任务。已有完成文件不会被覆盖；同名文件另加编号。

任务或设置 JSON 损坏且存在有效 `.bak` 时，会读取备份，并另存 `.damaged-时间编号` 保留损坏原件，启动后提示恢复。备份也不可读取时会停止启动并保留原文件，不创建空任务表覆盖它们。

「删除任务」先确认是否同时删除文件，默认勾选。取消勾选仅移除索引并保留文件；勾选则删除该任务的完成文件与专属未完成数据。BT 按原始种子中的文件清单清理，不递归删除整个保存文件夹；用户原来的 .torrent 和另放的文件保留。正在下载时需先暂停；文件被占用、越界或存在目录联接时保留任务并提示原因。在 Windows 设置中卸载「拾影下载管理」会移除安装清单里仍与原校验一致的程序文件和组件，保留 `data`、安装备份、成品和其他文件；修改过的程序文件也会保留。卸载会恢复安装前的注册值；指向另一安装位置的登记不会覆盖。安装与连接登记涉及：

- `HKCU\Software\Google\Chrome\NativeMessagingHosts\org.shiying.desktop`
- `HKCU\Software\Microsoft\Edge\NativeMessagingHosts\org.shiying.desktop`
- `HKCU\Software\Classes\shiying-desktop`
- `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\ShiyingDesktop`

## 开发

本目录 `Shiying.cs` 为下载和本机通信源码，`Torrent.cs` 为种子校验、文件选择窗口与独立 BT 会话，`Window.cs` 为主界面，`Details.cs` 为下载详情与进度数据，`Components.cs` 为固定版本组件准备，`Install.cs` 为安装登记与回滚，`Setup.cs` 为安装窗口。`build.ps1` 生成程序；准备已核验的核心 `bin/aria2c.exe` 与许可后，运行上级 `scripts/setup-payload.py`，再运行 `build-setup.ps1` 生成小体积安装器。三个视频组件不嵌入安装器。组件版本、来源和 SHA-256 见 `components.json`，许可见 `licenses`。测试源码位于上级 `scripts`；测试结果写入上级 `reports`。

离线管理检查：运行 `scripts/management-check.ps1`，会编译独立检查程序，只处理明确测试队列、临时文件和界面，不下载。悬浮检查为 `scripts/floating-check.cjs`。`scripts/startup-check.ps1` 使用隔离测试注册表根和本地字节样例检查安装与组件；不会在真实浏览器注册路径测试。

桌面代码采用 GPL-3.0-or-later，延续拾影的开源许可。第三方工具各自按原许可独立提供；公开分发前还需整理与所用二进制构建匹配的完整对应源码和发布材料。

本版使用与 Chrome 插件一致的 01 纯黑冰蓝配色，正文白色、辅助文字冰蓝，主窗口默认 920×640，可拖动边框调整大小及最大化。右上角可切换迷你窗，展开时回到原窗口大小和位置。程序声明系统 DPI 感知以减少系统位图拉伸，跨显示器显示效果仍以实际系统缩放为准。

窗口四边和四角保留原生缩放区域，网页内容不覆盖边缘；迷你窗使用当前系统 DPI 计算尺寸，修复 175% 缩放下内容宽度不足的问题。


主窗口退出时记住正常窗口尺寸、最大化和迷你窗状态；下次启动恢复，在屏幕缩放或分辨率变化时调整至可用范围。标题栏仅显示「拾影」，内容区去掉重复图标，版本号移入「关于拾影」。

### 0.4.24 BT 冷启动节点发现修正

修正仅对一个引导域名 ping 成功、却未取得可用于 get_peers 的路由入口的问题。首次启动 BT 内核时，在后台以总计最多 3 秒的预算并行尝试三个公开引导入口，先 find_node，再验证返回路由节点的事务号、节点 ID 和 get_peers token；使用通过验证的公网路由入口交给原 aria2 继续发现。请求不携带用户种子哈希。拒绝私网、回环、保留地址与零端口，长度和数量均有限制；失败时保留原始引导回退。已知私有任务和本机回归模式不执行额外公网引导。无可用全局 IPv6 地址时不启动 IPv6 DHT，避免持续发送失败请求。

零连接持续等待时，详情区区分“路由入口已验证”和“未能验证引导入口”；不把 0 连接等同于资源无源。仍需要供源在线且能够连接，发现地址不代表其拥有完整文件或可以达到特定速度。

验证包括本机 UDP 协议响应、错误事务、错误节点 ID、缺失 token、恶意地址和备用超时；真实原生内核使用随机哈希及仅元数据模式进行独立状态验证，没有下载用户视频。原来的文件勾选、暂停续传、重启续传、完成与删除行为保持。


### 0.4.25 BT 补源与连接优化

- 已确认文件列表和私有标记的公开种子，在新开始或手动续传时增加一次有边界的 IPv4 DHT 补充查找。查找在后台运行，最多 3.5 秒、24 个 UDP 请求、4 路并发，按目标 InfoHash 的 XOR 距离优先查询。最多保留 64 个有效候选地址，与近期已连接节点合并后通过原有仅监听 127.0.0.1 的短期缓存接口交给 aria2。新增候选不会绕过握手、分块校验或文件选择。
- 同一任务一分钟内不重复发起补充查找；暂停立即请求取消，迟到结果不能覆盖已暂停或已移除任务的缓存。失败或超时回到原 Tracker、DHT、PEX，不把补充查找失败变成下载失败。活动任务不会因为补充查找被重启或断开连接；持续发现仍由原内核负责。
- 已知私有种子、尚未确认文件列表的磁力任务不走这条额外补源路径。补充查询验证事务号、节点 ID、token 和紧凑地址格式，排除私网、保留地址、零端口及重复候选。只在内存中使用补充地址；原持久化缓存仍只记录实际已连接节点。
- 每个任务的连接上限从 96 调整为 128；积极寻找更多连接的速度门槛从 1 MiB/s 提高到 5 MiB/s。用户设置更低的下载限速时，继续以用户限速为准。这个值是寻找更多连接的门槛，不是最低速度承诺；不设置无限连接、不提高默认上传预算、不缩短外部 Tracker 要求的请求间隔。
- 本地检查使用独立目录、实际 aria2 和本机生成的字节，覆盖所选文件、补源接口消费、暂停/续传、跨进程恢复、损坏数据修复和完成状态。另用之前核对过来源的公开 Debian ISO 种子只查询候选地址，不建立其内容连接、不下载 ISO 或视频。候选地址不是已经验证可连接或拥有完整内容的供源，实际公网速度提升尚未验证。
- 本次仅生成安装预览，不覆盖正在运行的 0.4.24，不改用户任务和配对，也不更新已加载的 Chrome 插件。待用户下载完成并正常退出后，再安装本地新版。


### 0.4.26 关闭响应修正

保留 0.4.25 的 BT 补源与连接优化。点击主窗口或迷你窗的关闭按钮，以及托盘菜单退出时，先保存窗口尺寸、立即隐藏主窗口和所属详情窗、移除托盘图标，下载任务的安全保存和内核断开继续在后台完成。后台清理仍完成后才真正退出进程，不强制结束正常下载内核，不丢弃续传数据；清理期间重复关闭不重复执行，迟到的恢复或浏览器新建请求不把窗口重新弹出。

在独立私有测试桌面以实际 WinForms 关闭事件复现：人为让任务管理器忙 2.1 秒，旧版在后台清理期间窗口仍可见；修正后窗口在关闭请求返回前隐藏，仍完整等待后台清理、保留任务、部分数据和原窗口尺寸。测试不切换用户的输入桌面、不使用个人屏幕或鼠标、不下载媒体。
